# Build Order — phases 0–11 (+ V1/V2/V3 gates)

Conventions per phase: OBJ / PRE / DOMAINS / SCHEMA / SEC / TEST / EXIT / NOT-YET.

**Phase 0 — Bootstrap.** OBJ: monorepo + CI + env validation + local Supabase/PG run. PRE: ARCH ADRs signed. DOMAINS: config/auth/database skeleton. SCHEMA: `profiles`. SEC: env validation, secret-scan, no secrets in repo. TEST: build+lint+`db push` green. EXIT: `/healthz` + login round-trip locally. NOT-YET: any product table.

**Phase 1 — Identity/Workspace/RBAC.** OBJ: signup → workspace → invite → 5 roles + grants. PRE: 0 (+ S3 RLS spike complete — RLS helper pattern proven before first tenant table). DOMAINS: identity/workspace/authorization. SCHEMA: `workspaces, memberships, invitations, resource_grants`. SEC: RLS deny-default; invite RPC (Admin+, role ≤ own); membership writes RPC-only; grants RPC-minted only. TEST: RLS matrix (viewer cannot invite; member cannot self-promote; direct grant INSERT denied). EXIT: 2-user invite flow e2e. NOT-YET: forms.

**Phase 2 — Form schema + versioning.** OBJ: canonical schema lib + draft CRUD + immutable versions + publications. PRE: 1 (+ S1/S2 complete — engine + derivation proven before builder investment). DOMAINS: forms/forms-engine. SCHEMA: `forms, form_drafts, form_versions, form_publications, themes`. TEST: zod fuzz on 12 MVP field types (FIELDS.md); draft-edit-never-leaks-to-public; rollback = republish. EXIT: draft CRUD via UI+API with version pinning. NOT-YET: public links live.

**Phase 3 — Builder (draft only).** OBJ: palette/canvas/inspector, DnD, autosave, undo, rule editor + test mode. PRE: 2. DOMAINS: form-builder/ui. SCHEMA: none (client only). SEC: autosave requires Builder+. TEST: builder smoke (build→save→reload parity). EXIT: full form buildable without touching renderer code. NOT-YET: public renderer polish.

**Phase 4 — Publishing snapshot.** OBJ: publish/unpublish, unguessable publicId + optional slug, revision immutability. PRE: 2. DOMAINS: publishing. SCHEMA: live (from phase 2). SEC: public RLS = active publication only. TEST: draft N+1 never visible while vN served. EXIT: staged publish works end-to-end. NOT-YET: submissions.

**Phase 5 — Public renderer + embed.** OBJ: fast `/f/:publicId` + <5KB loader iframe embed + prefill + save-continue client. PRE: 4 (+ S5 complete — budgets proven on target devices before polish). DOMAINS: form-renderer. SCHEMA: none. SEC: no PII/workspace leak; Turnstile flag; slug enumeration defense. TEST: Lighthouse budgets + leak test. EXIT: p95 render targets met (see RENDERER-EMBED.md). NOT-YET: submit handling.

**Phase 6 — Submission pipeline.** OBJ: RPC-only intake (validated transactional submit) + quota gate + attachments refs + outbox event. PRE: 4, 5 (+ S4/S6 complete — query scale + AV pipeline proven before intake ships). DOMAINS: submissions/metering/files. SCHEMA: `submissions, submission_index, attachments, outbox, usage_counters`. SEC: transport checks before DB; server-side Zod revalidation in API/BFF pre-RPC; invariant enforcement inside intake RPC; single-use quarantine upload grants; idempotency keys; no anon table grants; least-privilege `intake_caller` EXECUTE-only role (never service-role in request path). TEST: k6 100rps [architecture target, S7-gated]; double-submit dedupe; spam quarantine; anon-direct-INSERT denied. EXIT: zero lost writes under retry. NOT-YET: email/webhooks.

**Phase 7 — Inbox + Tables.** OBJ: triage (tags/comments/assign/status/SLA) + grid views + async CSV export. PRE: 6. DOMAINS: inbox/tables. SCHEMA: `assignments, comments, tags, submission_reads, table_views, status_history`. SEC: assignee-scope reads; export = explicit grant + audit. TEST: 100k-row pagination; A→B isolation. EXIT: filter/sort/share-view/assign works. NOT-YET: notifications.

**Phase 8 — Async: notifications + webhooks + integrations-min.** OBJ: scheduled bounded outbox tick + retries/DLQ + 1 provider (Sheets or Slack) + public REST v1 + keys. PRE: 6 (+ S7/S9 complete). DOMAINS: notifications/webhooks/integrations/api. SCHEMA: `notifications, webhooks, webhook_deliveries, integrations, integration_runs, api_keys, outbox, processed_events, scheduled_jobs`. SEC: cron-secret tick auth, advisory-lock single-flight, HMAC signing, vaulted secrets, SSRF egress guard. TEST: tick idempotency (kill-mid-batch), retry/DLQ/replay; signature verify. EXIT: delivery success >99% happy path; zero lost events under worker kill. NOT-YET: billing.

**Phase 9 — Metering (no money movement).** OBJ: plan definitions, entitlements, counters + ledger, quota enforced end-to-end (402 + upgrade CTA), usage transparency screen; `BillingProvider` port as dead interface (no live keys). PRE: 6, 8 (+ S10 complete). DOMAINS: metering (+billing port stub). SCHEMA: `plans, usage_counters, usage_ledger`. No `subscriptions/invoices` tables in MVP. SEC: entitlements server-side; quota checks in-txn. TEST: quota-exceeded blocks intake with 402 UX; S10 concurrency proof; downgrade/cancel flows without payment. EXIT: over-quota behavior + usage screen + export-window verified; provider port compiles but disabled. NOT-YET: live checkout/subscriptions/invoices/refunds/top-ups (V1), AI/workflows.

**Phase 10 — Audit + analytics + files hardening.** OBJ: append-only audit, daily rollups, ClamAV worker path, PITR + restore drill. PRE: 6–9. DOMAINS: audit/analytics/files. SCHEMA: `audit_log, analytics_daily`. SEC: audit INSERT-only; AV fail-closed for executables. TEST: restore-from-backup drill; retention purge. EXIT: 30-day PITR verified. NOT-YET: enterprise SSO.

**Phase 11 — Hardening + launch.** OBJ: rate-limit tuning, abuse playbooks, SEO, status page, DPA docs, runbooks. PRE: all. DOMAINS: api/workspace. SCHEMA: none. SEC: top-10 review, secret rotation, pen-test fixes. TEST: load 500rps public; kill-worker chaos; full RLS matrix re-run. EXIT: SLOs met, runbook written, MVP fence satisfied. NOT-YET: any V1 feature.

**V1 gate:** phases 0–11, 12 MVP field types (FIELDS.md), 1 integration provider, live Razorpay (+Stripe) checkout with subscriptions/invoices/refunds/top-ups, single currency (₹). **V2:** workflows, payment collection in forms/UPI, PDFs/documents, portals, drop-off + scheduled reports, SSO, custom domains. **V3:** signatures, AI builder/agents, marketplace, HIPAA-ready region pin, white-label.
