# MVP Fence — what is IN, what is OUT, and where the hooks are

MVP must prove: `Auth → Workspace → Multi-admin RBAC → Resource grants → Audit → Canonical schema (MVP-12) → Versioning → Builder → Renderer → Publishing → Submission (RPC-only intake) → Inbox → Assignment/SLA → Tables → REST API → Webhooks → Metering (no-hostage) → Quarantine file pipeline`. Billing provider port exists as a dead interface (no live keys, no checkout); checkout/subscriptions/invoices/refunds/top-ups are V1. Anything outside this list is OUT — but every OUT item has a named, flagged-off extension point so nothing is painted shut.

## IN (must all work end-to-end before launch)
Auth (email + MFA-ready) · Workspace + invitations + 5 roles + resource grants + audit · Canonical schema + 12 MVP field types (FIELDS.md) + derivations + rule/calc v1 + test mode · Immutable publishedVersions + publications + rollback-by-republish · Builder (palette/canvas/inspector, DnD, autosave, undo, locks) · Public renderer (`/f/:publicId`, prefill, save-continue, offline queue) + <5KB embed loader [architecture target, Spike 5] · Submission pipeline (RPC-only intake: validate → captcha → rate-limit → idempotency → txn → outbox) · Inbox (search/filter/tags/comments/**assignee + status + SLA** + history) · Tables v1 (grid, filter/sort, inline edit, share with Read/Comment/Collaborate, async CSV export) · Webhooks (signing/retry/DLQ/logs) + REST v1 (keys, scopes, quotas, OpenAPI) · Metering (counters + ledger + quotas + usage screen + upgrade CTA; provider port dead-interface, NO live checkout) + Quarantined file pipeline + ClamAV path · Audit + rollups + PITR drill · Budgets met (renderer ≤50KB critical, p95 accept ≤500ms — both launch SLOs, proven in Spikes 4/5) · RLS matrix + isolation suite green.

## OUT (explicitly excluded from MVP)
Workflow engine · payments/subscriptions · e-signatures · PDF generation/editing + Smart-PDF-equivalent import · apps/portals/marketplace · AI generation/agents/insights · Salesforce/HubSpot deep sync (1 light provider only: Sheets or Slack) · SSO/SAML/SCIM · custom domains (slugs only) · residency/BAA posture · multi-currency (₹ only).

## Extension points left open (how OUT plugs in later without rework)
`form.published` / `submission.completed` events (workflows/AI consume without touching ingest) · version-pinned snapshots (PDF/sign render any version) · `BillingProvider` port (Stripe/international later) · OAuth-ready scopes + 1:1 MCP mapping (integrations/marketplace) · `role_templates` + grant table (custom roles, field-level policies) · `analytics_daily` rollups (scheduled reports, drop-off GA) · `region` column + portable SQL (residency) · `x-` widget namespace + PDF mapper hooks (signatures/payments/PDF fields) · `AuthProvider` interface (SSO providers).

## Why this fence
Each IN item is load-bearing for the differentiators (multi-admin included, fair metering, assignment/SLA, light embed, reliable API). Each OUT item is either regulated (payments/sign), model-risky (AI), or scaling-premature (apps/marketplace) — sequencing them later protects the MVP from scope explosion (risk R-01) while the extension points keep V1/V2/V3 on rails.
